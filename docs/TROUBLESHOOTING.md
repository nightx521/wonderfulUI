# 故障排查

## 启动后没有高光

WonderfulUI 默认读取：

```text
%USERPROFILE%\AppData\Roaming\ACLOS\WonderfulDb
```

请按顺序检查：

1. ACLOS/“无畏时刻”已经安装并登录。
2. 客户端已经在对局结束后生成过至少一段高光。
3. 等待高光写入完成，再回到 WonderfulUI 刷新资料库。
4. 仍然没有结果时，在设置中执行一次“全量扫描”。

本机扫描使用固定默认目录。已有导入历史时，即使本机 ACLOS 目录缺失仍可浏览资料库。
没有本机高光或历史记录时，首次使用页面会显示检测结果并提供旧电脑数据导入。

## 导入旧电脑的数据

1. 从旧电脑复制完整 WonderfulDb 文件夹，保留数字账户文件名和可选 snapshot；放在独立目录。
2. 在首次使用页面或“设置 → 资料库”点击“开始导入”，填写设备名称并选择此文件夹。
3. 选择视频在当前电脑上的存放目录，程序也会检查其子文件夹。
4. 查看预览，再点击“确认导入”。重复对局会合并，资料冲突时保留当前资料；失败账户跳过。

只有视频文件无法恢复账户、地图、英雄、对局和事件信息。匹配依据文件名、大小和路径
后缀；重名且无法唯一匹配的视频不会自动关联，详情会显示“视频未找到”。保留原始
WonderfulDb，整理好视频目录后可以重新导入同一份档案，重新匹配路径。改名、裁剪或覆盖
过的视频可能无法自动匹配。

导入只写 WonderfulUI 自己的 `%LOCALAPPDATA%\wonderful-ui\library.db`，源数据和视频
保持只读。全量扫描不会清除导入历史。可在筛选的“来源设备”选择本机或各导入设备；
来源作用于对局，同一对局属于多个来源时仍只显示一条，详情显示其全部合并视频。

## 扫描失败或部分账户缺失

“暂无本机高光”表示账户信息已读取，但主文件中没有高光记录。这不是读取失败；
snapshot 中有昵称或对局摘要也不代表生成过高光。回看已有记录无需启动录制客户端，
生成新高光则需要在录制客户端中启用相应功能。等待生成完成后刷新资料库。

真正失败的账户显示 `!`，悬停或选中后可看到错误类型、简短可能原因和处理提示：

| 提示 | 可能原因与处理 |
| --- | --- |
| 部分记录已跳过 | 个别记录缺少对局编号或编号冲突，正常对局已更新、原有资料保留；悬停账户查看跳过数量，源数据补全后刷新重试 |
| 账户文件未找到 | 文件被移动或正在更新，确认目录存在后刷新 |
| 无读取权限 | 当前 Windows 用户无访问权限，检查文件夹权限 |
| 暂时无法读取 | 文件被占用或正在写入，稍后刷新 |
| 文件内容异常 / 内容不完整 | 写入未完成或副本损坏，等候完成或核对原始副本 |
| 数据无法解密 | 文件不完整、数字文件名被改动或加密格式变化，保留原始名称并查看日志 |
| 数据格式暂不兼容 | 列表或字段结构变化，检查应用更新并提供脱敏日志 |
| 文件读取失败 / 账户读取失败 | 其它访问或格式异常，查看日志确认底层原因 |

以上是可能原因，不是对录制开关状态的判断。旧索引没有分类时先显示通用提示，
刷新后会重新分类；成功读取会清除此前错误。全量扫描不能生成源文件中缺少的高光。

ACLOS 正在写入 `WonderfulDb` 时，WonderfulUI 可能暂时无法解析文件。等待写入完成后
重新刷新；增量扫描仍然失败时，再执行“全量扫描”。全量扫描会重建 WonderfulUI 的
本地索引，不会修改 ACLOS 文件。

详细错误保存在：

```text
%LOCALAPPDATA%\wonderful-ui\logs\wonderful-ui.log
```

可以在设置的日志页面查看最近内容或打开日志目录。发送日志前，删去 openid、账户名、
用户名、绝对路径和其它无关数据。

账户详细失败记录在 `account-read` 范围，包含错误分类和底层错误；日志不会保存完整
解密后的账户内容。

## 视频无法播放或路径已经变化

WonderfulUI 使用 ACLOS 记录的原始视频路径，不会自动改写移动后的文件位置。

1. 重新挂载保存视频的磁盘、移动硬盘、NAS 或网络盘。
2. 确认视频仍然存在，当前 Windows 账户可以读取。
3. 回到应用执行全量扫描。
4. 如果文件已经被移动或删除，WonderfulUI 无法搜索新位置或恢复原视频。

## 快传无法访问

快传只在播放器中主动开启后监听 `22357/TCP`。扫码设备必须和电脑位于同一局域网。

1. 确认手机和电脑连接同一个 Wi-Fi 或 VLAN，不是访客网络。
2. 检查路由器是否开启 AP 隔离、客户端隔离或设备间访问限制。
3. 确认 Windows 防火墙允许 `WonderfulUI Quick Share` 规则。
4. 确认端口 `22357` 没有被其他程序占用。
5. 首次修复防火墙规则时，按 Windows 提示完成管理员授权。

企业策略、第三方防火墙和路由器隔离可能继续阻止访问，WonderfulUI 不会绕过这些限制。
关闭二维码时会等待快传服务退出并释放端口。下载仍在进行时，可以选择继续下载或停止下载。
端口冲突时，窗口显示可识别的占用程序；符合条件的程序可确认结束后重试。
系统、游戏相关或权限不足的程序需自行处理。完整卸载会删除对应的防火墙规则。

## 检查更新与覆盖升级

关于页更新按钮右侧的小箭头可选择代理加速（默认）或 GitHub 直连，选择会保存。
获取版本失败时先检查网络，再切换线路重试。签名失败时不会安装。


使用维护者提供的 Windows x64 NSIS 安装程序，核对项目来源、版本和校验值。
项目地址为 [nightx521/wonderfulUI](https://github.com/nightx521/wonderfulUI)，
当前为私密开发仓库，访问者需有仓库权限。

手动运行新版安装器时，默认选择“覆盖升级（保留资料和设置）”，沿用原安装目录即可，
不需要先卸载。资料库、导入设备和应用设置保留。

## 成就或对局结果缺失

升级后执行一次扫描，本机旧记录会重新读取 snapshot。旧版已经导入的档案如需补充
普通成就或结果事实，请重新导入同一份 WonderfulDb，已有对局会合并去重。
MVP/SVP 依据对局摘要，成就筛选中的“其他”包括普通对局及缺少成就记录的对局。
房间类型按主记录的 customgame 标记二分；没有该标记（包括模式缺失）归非自定义。
0:0 不会单凭比分显示平局：
有可靠胜负标记则显示胜/负，否则显示灰色“—”，悬停查看说明。
个人乱斗和异变轮战隐藏回合比分；当前不能可靠显示最终名次。

## 提交 Issue

报告普通问题时，请提供应用版本、Windows 版本、ACLOS 版本、复现步骤和脱敏日志。

不要公开真实路径、openid、昵称、视频文件名、快传 URL 或令牌。安全漏洞按
[安全策略](../SECURITY.md) 私密报告。

## 卸载与本地数据

NSIS 卸载器默认保留 WonderfulUI 的本地资料库和 WebView2 用户数据。需要清理资料库
时，可在卸载确认页勾选对应选项。卸载器不会修改或删除 ACLOS、游戏、Riot 或 Vanguard
目录；完整卸载会清理快传防火墙规则。
